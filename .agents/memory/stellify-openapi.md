# Stellify OpenAPI Hook Name Quirks

## Key gotchas

1. **`getStellarbBoard` (note double-b)** — operationId in spec is `getStellarbBoard` (matches the schema name `StellarbBoard`). Generated hook: `useGetStellarbBoard(params?, options?)`. Params type is `GetStellarbBoardParams` which only has `year?: number` as a query param — NOT a `query` wrapper.

2. **Params vs options**: Hooks with optional query params take `(params?, options?)`. Hooks with no params take `(options?)`. Always check the generated signature before passing `{ query: ... }` as first arg.

3. **`listEvents` params**: `useListEvents(params?, options?)` where params = `ListEventsParams { upcoming?: boolean }`. Pass `undefined` if not filtering.

## Why
Orval derives hook names from `operationId` in `openapi.yaml`. Collision with TS2308 is prevented by using entity-shaped body schema names (NoteInput not CreateNoteBody). See `.local/skills/pnpm-workspace/references/openapi.md`.

## How to apply
When adding new endpoints, check the generated hook signature in `lib/api-client-react/src/generated/api.ts` before writing frontend code. Never hand-write types that codegen produces.
